# KnowEdit target-token evaluation

Download a JSON test file from [zjunlp/KnowEdit](https://huggingface.co/datasets/zjunlp/KnowEdit/tree/main/benchmark). Supported files are `benchmark/ZsRE/ZsRE-test-all.json`, `benchmark/wiki_counterfact/test_cf.json`, `benchmark/wiki_recent/recent_test.json`, and `benchmark/WikiBio/wikibio-test-all.json`.

For example, after downloading the ZsRE test file:

```sh
python infer.py --knowedit-file benchmark/ZsRE/ZsRE-test-all.json --knowedit-index 1-10 --max-new-tokens 64
```

`--replay-perturbation first.pt second.pt` accepts one or more saved perturbation files. With multiple files, replay continues to the end of the longest file and averages the available nonzero vectors at each position. Exhausted files and all-zero vectors are excluded from that position's average; if all available vectors are zero there, the effective vector remains an early-exit marker. Vector shapes must match across files. For a free-form prompt, place the prompt before this multi-value option.

When replaying one or more files, perturbation checkpoint saving is disabled, including the default checkpoint and any explicit `--save-perturbation` path. Replay never overwrites the input checkpoints. Result and debug JSON output are still written normally.

To generate from a variant instead of the main question, use `--knowedit-variant portability`, `--knowedit-variant rephrased_prompt`, or `--knowedit-variant locality`. Use `--knowedit-variant-index N` to select the Nth prompt (1-based, default 1) within that variant; nested portability/locality categories are flattened in file order. For example, `--knowedit-variant locality --knowedit-variant-index 2` selects the second locality prompt. Each selected record must contain that prompt. The rephrased variant is a single string stored under `rephrase_prompt`, `rephrased_prompt`, or `rephrase`, so only index 1 applies. Target-directed perturbation uses `target_new` for rephrased prompts and the selected question's `ground_truth` for portability/locality (the first answer when alternatives are nested). The original `target_new` and `ground_truth` scores remain tied to the main question. Automatic output and saved perturbation filenames include the variant and its index.

Indices are 1-based; ranges and negative indices (counting from the end) work as for the other tasks. Omit `--knowedit-index` to run the entire file. Each output record includes `knowedit_target` (`target_new`) and, where provided, `knowedit_ground_truth`. Each run scores both independently using teacher-forced next-token accuracy: `knowedit_ground_truth_acc` for the original answer and `knowedit_target_new_acc` for the proposed edit. Records with `portability` also score each nested question against its own `ground_truth`, using a separate target-blind prompt and fresh cache. Each run stores these under `knowedit_portability` with category, prompt, ground truth, and accuracy; the terminal summary averages accuracy across portability questions. The terminal prints the top two predictions and their full-vocabulary softmax probabilities at each token position for each available reference, regardless of whether they match. Summary means show how many selected records had that reference. ZsRE and WikiCounterFact provide `ground_truth`; WikiRecent and WikiBio do not, so they receive only the target-new score (WikiBio uses `labels` as the continuation target). A fresh model cache uses the same recirculation settings as the corresponding run; each reference token is fed only after its prediction has been scored. `--do-eval` does not call OpenAI or a separate evaluation model for KnowEdit.

Fact and QA generation prompts contain only the question or completion statement, never a reference answer. During teacher-forced scoring, gold tokens are present in the model input only *after* their predictions have been measured. These scores do not assume the model is edited: compare the accuracies for the model you actually ran. **Without an editing step and pre/post comparison, these scores are not KnowEdit edit success, portability success, or locality preservation; locality variants are generated but not separately scored.** Dynamic recovery options triggered by freely generated text are not replayed during teacher-forced scoring. ConvSent and Sanitation have different schemas and are not supported by this task.
